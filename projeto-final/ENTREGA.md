# Guia de Entrega e Apresentação

## Sprint 2

- Entregar a primeira página do site estruturada no GitHub Pages.
- Entregar um mini GDD do game atendendo à persona.
- Garantir que a primeira página explique claramente o problema do Fábio e direcione para o protótipo.

## Entrega Final

- Enviar um arquivo ZIP com a versão final do projeto.
- Enviar o endereço do repositório no GitHub.
- Enviar o endereço da página hospedada no GitHub Pages.
- Revisar se o site abre direto pelo index.html e se o protótipo funciona no navegador.

## Mesmo repositório ou outro?

- O mais seguro é usar o mesmo repositório público desde a Sprint 1 até a entrega final.
- Isso mostra evolução real do projeto: persona, primeira página, protótipo e versão final no mesmo histórico.
- Como a Sprint 1 já exigia versionamento real, manter tudo no mesmo repositório fortalece sua entrega.
- Só crie outro repositório se o professor tiver pedido isso de forma explícita.

## Como organizar as sprints no mesmo repositório

1. Mantenha a persona que você entregou na Sprint 1 dentro do repositório.
2. Adicione na Sprint 2 a primeira página do site, o protótipo e o mini GDD.
3. Faça novos commits mostrando cada avanço do projeto.
4. Na entrega final, envie o mesmo link do repositório, agora com a versão mais completa.
5. Se quiser, crie um README explicando o que foi entregue em cada sprint.

## Passo a Passo GitHub

1. Criar um repositório novo no GitHub.
2. Enviar todos os arquivos da pasta do projeto para esse repositório.
3. Confirmar que o index.html está na raiz do projeto.
4. Fazer o primeiro commit com uma mensagem clara, como "Entrega Sprint 2 - Rota".

## Como colocar o site no ar

1. Confirme que o arquivo principal do site é o index.html.
2. Suba todos os arquivos atualizados para o mesmo repositório.
3. Ative o GitHub Pages nas configurações do repositório.
4. Aguarde o GitHub gerar o link público.
5. Abra o link e teste navegação, jogo e páginas internas.
6. Use esse link como o endereço do site hospedado na entrega.

## Passo a Passo GitHub Pages

1. Abrir o repositório no GitHub.
2. Ir em Settings.
3. Abrir a seção Pages.
4. Em Build and deployment, escolher Deploy from a branch.
5. Selecionar a branch main.
6. Selecionar a pasta /(root).
7. Salvar e aguardar a publicação.
8. Testar o link gerado pelo GitHub Pages.

## Como Gerar o ZIP

1. Fechar arquivos temporários desnecessários.
2. Selecionar a pasta do projeto.
3. Clicar com o botão direito.
4. Escolher Enviar para > Pasta compactada.
5. Conferir se o ZIP contém index.html, css, js, game.html e GDD.md.

## Roteiro de Apresentação

1. Comece apresentando a persona Fábio Alves.
2. Explique a dor principal: esquecimento de rotas, combustível e cansaço.
3. Mostre a primeira página do site e diga como ela foi pensada para a persona.
4. Abra o protótipo e demonstre rapidamente a lógica do jogo.
5. Relacione o que aparece no jogo com os elementos do mini GDD.
6. Encerre mostrando que o projeto está pronto para GitHub, GitHub Pages e envio em ZIP.

## Fala Curta Sugerida

"Nosso projeto parte da persona Fábio Alves, motorista de van universitária que trabalha à noite e enfrenta dificuldade para lembrar rotas, controlar combustível e lidar com o cansaço. Criamos o Rota, uma primeira página para apresentar esse contexto e um protótipo jogável que transforma esse problema em experiência interativa. O mini GDD organiza a visão do jogo, suas mecânicas e a relação direta com a persona. A entrega está pronta para ser publicada no GitHub Pages e enviada em ZIP, como a faculdade solicitou."
